# 10 天急救計劃（資深開發者專用）

> [!warning] 適用條件（三項都要符合）
> 1. 你有 **2 年以上實際使用 Google Cloud** 的開發經驗（不是只讀過文件）。
> 2. 你**已經在生產環境**部署過 Cloud Run 或 GKE。
> 3. 你能接受「冷門考點直接放棄」的策略。
>
> 不符合的話請用 [[25 天衝刺計劃]]。10 天版是**補洞**，不是學習。

## 🎯 策略：只補三種洞

| 洞的類型 | 症狀 | 補法 |
|---|---|---|
| **判準洞** | 兩個服務都能做，不確定 Google 偏好哪個 | 三張決策樹背到能默寫 |
| **數字洞** | 知道有上限，不記得數字 | [[數字與限制速記]] 每天讀一遍 |
| **盲區洞** | 工作上沒碰過的服務（常見：Spanner、Bigtable、Apigee、Binary Auth、WIF、Vertex AI） | 每篇只讀「一句話定位 + 考點速記 + 真實場景陷阱」 |

## ✂️ 明確放棄的東西（10 天版的取捨）

- 所有 Lab（除非你完全沒部署過 Cloud Run → 至少做 [[Lab 01 Cloud Run 端到端]]）
- App Engine 與 Compute Engine 的細節（只記 [[Compute Engine 與 App Engine]] 的定位表）

- Workflows 的語法細節（只記能力邊界）
