# 00 技術關聯地圖

> [!abstract] 這篇跟 [[00 服務索引]] 差在哪
> **服務索引回答「有哪些服務」（分類清單）；這篇回答「它們怎麼串在一起」（資料流與依賴）。**
> 四條主線串起整個雲端原生系統。每個節點都可以點進去看細節。

## ① 一個請求的完整生命週期

從使用者按下按鈕，到資料寫進資料庫再回來，中間經過的每一層。

```mermaid
flowchart TD
    U["👤 使用者 / 行動 App"]
    U -->|"HTTPS"| EDGE

    subgraph EDGE["邊緣層"]
        CDN["Cloud CDN<br/>靜態內容命中就直接回"]
        ARMOR["Cloud Armor<br/>WAF / DDoS / IP 封鎖"]
        LB["Global External ALB<br/>anycast IP + TLS 終結 + session affinity"]
        CDN --- LB
        ARMOR --- LB
    end

    LB -->|"Serverless NEG"| GATE
    subgraph GATE["API 前門（可選）"]
        AG["API Gateway / Apigee<br/>API key / JWT 驗證 / 限流 / 版本"]
        IAP["IAP<br/>內部應用的身分守門"]
    end

    GATE --> COMPUTE
    subgraph COMPUTE["運算層"]
        CR["Cloud Run 服務<br/>concurrency / 自動擴充 / revision"]
        GKE["GKE Pod<br/>probe / HPA / requests-limits"]
    end

    COMPUTE -->|"ADC 取得 token"| ID["服務身分<br/>Service Account / Workload Identity"]
    ID -->|"IAM 授權"| DATA
    COMPUTE -->|"讀祕密"| SM["Secret Manager"]

    COMPUTE -->|"① 先查快取"| CACHE["Memorystore<br/>亞毫秒"]
    CACHE -.->|"miss"| DATA

    subgraph DATA["資料層"]
        SQL["Cloud SQL / AlloyDB<br/>連線池 + Auth Proxy"]
        FS["Firestore"]
        SP["Spanner"]
        BT["Bigtable"]
        GCS["Cloud Storage"]
    end

    COMPUTE -->|"Direct VPC egress"| VPC["VPC<br/>私有 IP / Cloud NAT"]
    VPC --> SQL
    VPC --> CACHE

    COMPUTE -->|"非同步：回應先送出"| ASYNC["Pub/Sub · Cloud Tasks"]
    COMPUTE -->|"每個階段都發出"| OBS["Logs · Metrics · Traces"]

    click CR "Cloud Run"
    click GKE "GKE 基礎與 Autopilot"
```

## ② 資料層的依賴、一致性與容錯

「這份資料放哪裡、壞掉時影響多大、讀到的是不是最新的。」

```mermaid
flowchart TB
    APP["應用"] --> Q{"資料的性質?"}

    Q -->|"檔案 / 大物件"| GCS["Cloud Storage<br/>強一致 · region/multi-region<br/>lifecycle 控成本 · signed URL 授權"]
    Q -->|"暫時 / 亞毫秒"| MS["Memorystore<br/>Basic=單點 · Standard=跨zone HA"]
    Q -->|"分析 / 報表"| BQ["BigQuery<br/>分區+叢集控成本"]
    Q -->|"營運型 OLTP"| OLTP

    subgraph OLTP["營運型資料庫"]
        direction LR
        SQL["Cloud SQL / AlloyDB<br/>主庫強一致<br/>HA=同region跨zone"]
        SP["Spanner<br/>外部一致<br/>multi-region 99.999%"]
        FS["Firestore<br/>強一致 · 可縮到0"]
        BT["Bigtable<br/>單叢集強一致<br/>跨叢集最終一致"]
    end

    SQL -->|"非同步複寫<br/>⚠️ 最終一致、不能寫"| RR["Read Replica"]
    RR -.->|"讀到舊資料"| RYW["read-your-writes 問題<br/>→ 關鍵讀走主庫"]

    MS -.->|"快取與 DB 不一致"| INV["失效策略<br/>更新 DB → 刪快取<br/>TTL 加抖動防雪崩"]

    OLTP -->|"寫入 + 同交易寫 outbox"| OUT["Transactional Outbox"]
    OUT --> PS["Pub/Sub"]
    PS -.->|"at-least-once"| IDEM["消費端冪等"]

    OLTP -->|"匯出 / 串流"| BQ
    GCS -->|"批次載入（免費）"| BQ
    PS -->|"BigQuery 訂閱（免程式碼）"| BQ

    ZONE["zone 故障"] -.->|"自動撐過"| SQL
    ZONE -.->|"自動撐過"| MS
    REGION["region 故障"] -.->|"只有這個自動撐過"| SP
```

## ③ 從 commit 到上線的交付鏈

每一個箭頭都是一道可以插入檢查的關卡。

```mermaid
flowchart LR
    DEV["👨‍💻 開發<br/>Cloud Code / Workstations<br/>+ emulator 本地測試"]
    DEV -->|"git push"| TRIG["Cloud Build Trigger<br/>分支 / PR / tag"]

    subgraph CI["Cloud Build（CI）"]
        direction TB
        T1["lint + unit test<br/>(平行 waitFor: '-')"]
        T2["整合測試<br/>（emulator）"]
        T3["build image<br/>(cache-from)"]
        T1 --> T2 --> T3
    end
    TRIG --> CI

    CI -->|"push + provenance"| AR["Artifact Registry<br/>digest 為準 · cleanup policy"]
    AR --> AA["Artifact Analysis<br/>CVE 掃描（含持續分析）"]
    CI -->|"用 KMS 金鑰簽章"| ATT["Attestation<br/>build / qa / security"]

    AR --> CD["Cloud Deploy（CD）<br/>同一個產出物晉升"]
    ATT --> BA{"Binary Authorization<br/>REQUIRE_ATTESTATION"}
    CD --> BA
    BA -->|"❌ 缺簽章"| BLOCK["阻擋部署"]
    BA -->|"✅"| DEP

    subgraph DEP["部署"]
        D1["dev"] -->|"promote"| D2["staging"] -->|"✋ 核准"| D3["prod<br/>canary 25→50→100"]
    end

    D3 --> VERIFY["verify 階段<br/>自動 smoke test"]
    VERIFY -->|"SLO 惡化"| RB["回滾<br/>Cloud Run: update-traffic<br/>GKE: rollout undo"]
    VERIFY --> OK["✅ 上線"]

    OK -.->|"資料變更不能回滾"| MIG["schema 用 expand→migrate→contract"]
```

## ④ 可觀測性的訊號流

一個請求產生三種訊號，三種訊號靠 **trace ID** 縫在一起。

```mermaid
flowchart TB
    REQ["請求進入<br/>產生 trace ID"] --> OTEL["OpenTelemetry SDK<br/>自動 + 手動 instrumentation"]

    OTEL -->|"注入 traceparent"| DOWN["下游服務<br/>（繼承同一個 trace）"]
    DOWN -.->|"跨 Pub/Sub 要放進訊息屬性"| OTEL

    OTEL --> COL["OTel Collector<br/>取樣 · 去 PII · 批次"]

    COL --> TR["Cloud Trace<br/>span 瀑布圖 → 哪一段慢"]
    COL --> MET["Cloud Monitoring<br/>四個黃金訊號"]
    OTEL -->|"stdout 結構化 JSON<br/>+ logging.googleapis.com/trace"| LOG["Cloud Logging"]

    LOG -->|"severity≥ERROR + 完整 stack trace"| ER["Error Reporting<br/>相同例外聚合成 issue"]
    LOG -->|"log-based metric"| MET
    LOG --> ROUTER["Log Router / Sink"]
    ROUTER --> ARCH["GCS 歸檔"]
    ROUTER --> BQ2["BigQuery 分析"]
    ROUTER --> SIEM["Pub/Sub → 外部 SIEM"]

    MET --> SLO["SLO + error budget"]
    SLO --> BURN["burn-rate 警示<br/>（取代吵雜的固定門檻）"]
    BURN --> ONCALL["通知：Slack / PagerDuty /<br/>Pub/Sub → 自動修復"]

    PROF["Cloud Profiler<br/>CPU / heap 熱點"] -.->|"瓶頸在自己的程式碼時"| TR

    TR -->|"同一個 trace ID"| LOG
    ER -->|"同一個 trace ID"| LOG
```

**排查順序（考題愛問「你會先做什麼」）**
```
Monitoring 看 SLI（有問題嗎）
  → Trace 找最慢的 span（在哪裡）
    → Logging 用 trace ID 撈上下文（為什麼）
      → Profiler 找熱點函式（哪一行）
```

## 🔁 四條主線的交會點

這幾個概念**橫跨多條主線**，也是考試最愛的整合題來源：

| 交會概念 | 出現在哪幾條線 | 核心筆記 |
|---|---|---|
| **服務身分（SA / Workload Identity）** | ①運算→資料、③CI 部署、④送 telemetry | [[IAM 與服務帳戶]] |
| **冪等** | ②資料寫入、非同步串接、③重試部署 | [[韌性模式 重試 冪等 退避 斷路器]] |
| **trace ID** | ①請求穿越所有層、④縫合三種訊號 | [[OpenTelemetry 與 Trace 關聯]] |
| **不可變產出物（digest / revision）** | ③交付鏈、①部署與回滾 | [[Cloud Deploy 與部署策略]] |
| **VPC 私有連線** | ①運算→資料、③private worker pool | [[VPC 連線 Serverless VPC Access 與 Direct VPC Egress]] |
| **向後相容** | ②schema 變更、③漸進式發布、API 版本化 | [[API 設計 REST 與 gRPC]] |
| **成本槓桿** | ①concurrency/實例數、②儲存分層、④log 與指標量 | [[成本與資源最佳化]] |
