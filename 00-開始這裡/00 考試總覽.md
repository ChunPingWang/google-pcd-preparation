# 00 考試總覽

## 📋 考試規格（官方，查核日 2026-09-27）

| 項目 | 內容 |
|---|---|
| 正式名稱 | Google Cloud Certified – **Professional Cloud Developer** |
| 時間 | **2 小時**（120 分鐘） |
| 題數 | **50–60 題**，單選 + 多選（multiple choice / multiple select） |
| 費用 | **USD $200**（另計稅） |
| 語言 | **英文、日文**（無中文，考題要讀英文） |
| 形式 | 線上監考（remote）或考場監考（onsite） |
| 先修條件 | 無 |
| 建議經驗 | 3 年以上業界經驗，其中 1 年以上使用 Google Cloud |
| 有效期 | **2 年**，到期前可在資格期間內續證 |
| 通過分數 | **官方不公布**。社群普遍以 70% 為安全線 → 準備時以「模擬題穩定 80%」為目標 |
| 案例研究 | **無**（不像 Professional Cloud Architect 有 case study） |

> [!info] 題型特徵
> PCD 是「**開發者視角的 Architect 題**」：
> - 大量「給你一個需求 → 選最合適的服務 / 設定」的情境題。
> - 少量但確實會考的「這段 gcloud / YAML / 程式碼哪裡錯」。
> - 幾乎不考背指令參數的細節，但會考 **預設值與上限**（例如 Cloud Run 預設 concurrency、Pub/Sub ack deadline）。

## 🎓 官方對「PCD」的角色定義（2026 版新增重點）

官方指南對這個角色的描述在 2026 版明顯擴張，除了傳統的雲端原生開發，**新增了 AI 相關職責**：

1. 用 Google 建議的工具與最佳實務，建置與設定**可擴充、安全**的應用。
2. 熟悉**完整開發生命週期**：從架構設計 → 建置 → 測試 → 部署 → 維運。
3. **整合機器學習能力**，使用 **生成式 AI API** 打造智慧使用者體驗。
4. 善用 **AI 輔助開發工具**（AI coding assistant、context engineering、自動化 debug agent）加速交付與提升品質。

> [!important] 對備考的實際影響
> 舊版考古題（2022–2024）少了三塊，一定要補：
> - **Gen AI / Vertex AI**：見 [[Vertex AI Gemini API 給開發者]]
> - **AI 開發工具鏈**：Gemini Code Assist、Gemini Cloud Assist、Cloud Workstations、MCP server → 見 [[開發環境 Cloud Code Shell Workstations 與 AI 工具]]
> - **新一代服務**：AlloyDB、Cloud Service Mesh、Direct VPC egress、Artifact Analysis、Cloud Deploy → 對應筆記都已收錄

## 🧩 四大範圍與權重

| # | Section | 權重 | 子範圍 | 筆記 |
|---|---|---|---|---|
| 1 | 設計可擴充、安全、可靠的雲端原生應用 | **~32%** | 1.1 高效能應用與 API｜1.2 安全應用｜1.3 資料儲存與存取 | [[Section 1 設計可擴充安全可靠的雲端原生應用]] |
| 2 | 建置與測試應用 | **~23%** | 2.1 開發環境｜2.2 建置｜2.3 測試 | [[Section 2 建置與測試應用]] |
| 3 | 設定雲端原生應用的部署 | **~24%** | 3.1 部署到 Cloud Run｜3.2 部署容器到 GKE | [[Section 3 設定雲端原生應用的部署]] |
| 4 | 整合應用與 Google Cloud 服務 | **~21%** | 4.1 資料與儲存整合｜4.2 使用 Cloud API｜4.3 疑難排解與可觀測性 | [[Section 4 整合 Google Cloud 服務]] |

> [!tip] 權重的策略意義
> - **Section 1 + 3 = 56%**：`Cloud Run` 與 `GKE` 合起來是考試的主軸。若時間不夠，先把這兩個服務吃到「能教別人」。
> - Section 2 只有 23%，但**題目最容易拿分**（Cloud Build / Artifact Registry / 模擬器的考點固定），投報率最高。
> - Section 4 的可觀測性（4.3）常被低估，但 `trace ID 關聯`、`log-based metrics`、`Error Reporting` 幾乎必考。

## 🧠 高頻主題排行（依社群回報 + 指南密度推估）

1. **Cloud Run**：修訂版本（revision）、流量分流、並行、擴充、服務身分、觸發器
2. **GKE**：health check（三種 probe）、HPA、requests/limits、Autopilot vs Standard
3. **IAM / 服務帳戶 / 最小權限**：誰該有什麼角色、ADC 怎麼運作
4. **Pub/Sub**：at-least-once、ack deadline、dead-letter、ordering、冪等消費
5. **資料庫選型**：Firestore vs Spanner vs Bigtable vs Cloud SQL/AlloyDB
6. **Cloud Build + Artifact Registry**：CI 流程、provenance、Binary Authorization
7. **可觀測性**：結構化 log、trace 關聯、log-based metric、Error Reporting
8. **Cloud Storage**：storage class、lifecycle、signed URL、retention lock
9. **Secret Manager / KMS / Workload Identity Federation**
10. **部署策略**：canary / blue-green / 漸進式流量、rollback

## 🎯 及格心態與答題策略

> [!example] 四個答題原則（考場實用）
> 1. **找「最 Google 的答案」**：題目沒有特別限制時，Google 偏好 *全代管 > 半代管 > 自建*、*serverless > VM*、*託管身分（WIF / 服務帳戶）> 金鑰檔案*。
> 2. **鎖定關鍵限制詞**：`minimal operational overhead`（選全代管）、`minimal code change`（選 lift-and-shift / GKE）、`strong consistency`、`global`、`sub-10ms`、`petabyte`、`cost-effective` — 每個詞都直接砍掉一半選項。
> 3. **排除法優先**：專業級考試的錯誤選項通常犯了「服務根本不支援」或「違反最小權限」的硬錯。先砍硬錯，再比兩個似乎都對的。
> 4. **標記可疑題**：50–60 題 / 120 分鐘 → 平均 **2 分鐘/題**。超過 2.5 分鐘就標記跳過，留最後 20 分鐘回頭。

### 常見的兩難與判準

| 兩難 | 判準 |
|---|---|
| Cloud Run vs GKE | 要不要 sidecar/DaemonSet/自訂排程/多協定？要 → GKE。否則 Cloud Run |
| Pub/Sub vs Cloud Tasks | 一對多廣播/串流 → Pub/Sub；**單一目標 + 每任務控制速率/排程** → Cloud Tasks |
| Firestore vs Spanner | 行動端/即時同步/文件模型 → Firestore；需要 SQL + 全球強一致交易 → Spanner |
| Memorystore vs CDN | 動態資料/session → Memorystore；靜態內容邊緣快取 → Cloud CDN |
| Secret Manager vs KMS | 存**祕密本身** → Secret Manager；管**加密金鑰** → KMS |
