# 考前 48 小時衝刺

> [!danger] 這 48 小時不要做的事
> - ❌ 讀新服務、開新的官方文件章節
> - ❌ 刷新的題庫（會打擊信心且來不及修正）
> - ❌ 熬夜。睡眠不足對情境題的判斷力傷害極大
>
> 這兩天的唯一任務是：**把已經學過的東西變得可以快速提取。**

---

## ⏳ T-48h（考前第二天）

### 上午（90 分）— 決策樹默寫
- [ ] 蓋住筆記，在白紙上畫出三張決策樹，然後對照：
  - [[決策樹 運算平台選型]]
  - [[決策樹 資料庫選型]]
  - [[決策樹 訊息與事件選型]]
- [ ] 畫不出來的分支 → 回該篇筆記只讀那一段

### 下午（90 分）— 數字與限制
- [ ] [[數字與限制速記]] 唸出聲讀完一遍
- [ ] 自測：遮住答案欄，能答出 80% 才算過
- [ ] 特別確認這幾組（最常考）：
  - Cloud Run：預設 concurrency、預設/最大 timeout、最大記憶體/CPU
  - Pub/Sub：預設 ack deadline、最大 ack deadline、訊息保留期、最大訊息大小
  - Firestore：文件大小上限、單文件寫入頻率
  - Cloud Storage：各 storage class 的最短儲存期
  - GKE：probe 的預設值、HPA 的預設同步週期

### 晚上（60 分）— 錯題卡
- [ ] 把所有錯題卡讀一遍，只看「一句話教訓」
- [ ] 搜尋 `tag:#weak`，把還有的逐條解決或**明確放棄**（放棄也是策略）

## ⏳ T-24h（考前一天）

### 上午（60 分）— 陷阱與讀題
- [ ] [[常見陷阱與誘答選項識別]] 完整讀一遍
- [ ] 練習：隨機挑 10 題只做「圈出關鍵限制詞 → 說出應該選哪類服務」，不用真的選答案

### 下午（60 分）— 心智模型口頭複述
不看筆記，用嘴巴講完這 8 條。講不順的回去補：

1. 一個 HTTP 請求進到 Cloud Run 服務，從 LB 到容器再回來，經過哪些東西？
2. `kubectl apply` 一個 Deployment 之後，K8s 做了哪些事讓 Pod 真的收到流量？
3. 服務 A 呼叫需要驗證的服務 B，token 從哪來、誰驗證、失敗會回什麼？
4. 一則 Pub/Sub 訊息從 publish 到被成功處理，中間有幾個可能重複/遺失的點？
5. `git push` 之後到新版上線，經過哪些關卡（建置、掃描、簽章、部署、驗證）？
6. 一筆寫入 Spanner 和寫入 Firestore，一致性保證差在哪？
7. 使用者說「網站很慢」，你依序打開哪些可觀測性工具、看什麼指標？
8. 要把一個 VM 上的單體應用搬到雲端原生，你的分階段路線是什麼？

### 晚上（30 分）— 後勤
- [ ] **證件**：政府核發的照片證件，姓名要和報名完全一致
- [ ] **線上監考**：跑一次系統檢查（webcam、麥克風、網速），關掉所有其他程式
- [ ] **環境**：桌面清空、牆上無紙張、房間無他人、手機收起
- [ ] **時間**：確認考試時區與開始時間，提早 15 分鐘就位
- [ ] 準備水（線上監考通常允許透明容器，以考場規則為準）
- [ ] 22:00 停止讀書，睡滿 7 小時

## 🏁 考試當天

### 開考前 10 分鐘（只看這個）
腦中快速跑一遍**四個關鍵詞映射**：

| 題目出現 | 直接想到 |
|---|---|
| `minimal operational overhead` / `no infrastructure management` | Cloud Run、Firestore、Pub/Sub（全代管） |
| `minimal code changes` / `lift and shift` | GKE、Compute Engine、MIG |
| `globally consistent` + `relational` + `horizontal scale` | Spanner |
| `time-series` / `petabyte` / `single-digit ms` / `high throughput writes` | Bigtable |
| `sub-millisecond` / `session` / `cache` | Memorystore |
| `at-least-once` / `duplicate messages` | 冪等鍵 + dead-letter topic |
| `long-running task` + `HTTP 觸發` | Cloud Tasks / Cloud Run Jobs / Workflows |
| `no service account keys` | Workload Identity Federation |
| `only signed images` | Binary Authorization |
| `grant temporary access to an object` | signed URL |
| `correlate requests across services` | trace ID / Cloud Trace + OpenTelemetry |

### 答題節奏
- 目標：**第 60 分鐘做到第 30 題**。落後就加快、放棄糾結。
- 第一輪：能 30 秒內決定的直接選；猶豫的先標記，選一個最像的答案（**不要留空**）。
- 第二輪（最後 20 分鐘）：只看標記題。此時腦中已有更多線索，常會突然看懂。
- **多選題（Choose two/three）**：先確認要選幾個，再用「哪些明顯錯」反推。

### 考場心態
- 遇到完全沒見過的服務名 → 很可能是誘答或新功能，用**排除法**處理，別慌。
- 連續三題都不確定是正常的，不代表會不及格（門檻約 70%，可以錯 15 題以上）。
