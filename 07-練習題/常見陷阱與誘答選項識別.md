# 常見陷阱與誘答選項識別

> [!danger] 這篇可能直接值 5～10 分
> 專業級考試的錯誤選項**不是隨便亂寫的**，它們都針對特定的認知盲點。
> 認出誘答的套路，比多背一個服務有效。

---

## 🔑 Part 1：關鍵限制詞 → 直接砍一半選項

| 題目出現 | 意思 | 選 | 砍掉 |
|---|---|---|---|
| `minimal operational overhead` / `no infrastructure to manage` / `fully managed` | 要全代管 | Cloud Run、Firestore、Pub/Sub、BigQuery、Autopilot | 自建、VM、GKE Standard |
| `minimal code changes` / `lift and shift` / `as-is` | 不能改程式 | Compute Engine、GKE、MIG | 重寫成 serverless |
| `most cost-effective` + 間歇流量 | 要能縮到 0 | Cloud Run | GKE、VM、Bigtable |
| `globally` + `strongly consistent` + `relational` | 三個條件同時 | **Spanner** | Cloud SQL + replica |
| `single-digit millisecond` + `petabyte` + `time-series` | 超大規模低延遲 | **Bigtable** | Firestore、BigQuery |
| `sub-millisecond` | 記憶體層級 | **Memorystore** | 任何資料庫 |
| `offline support` / `real-time listeners` / `mobile SDK` | 客戶端直連 | **Firestore** | Cloud SQL、Bigtable |
| `analytics over terabytes with SQL` | 分析型 | **BigQuery** | Bigtable、Spanner |
| `without service account keys` | 免金鑰 | WIF、附加 SA、Workload Identity | 金鑰檔案（永遠是錯的） |
| `only signed / verified images` | 准入控制 | **Binary Authorization** | 只做掃描 |
| `temporary access to one object` | 限時存取 | **signed URL** | 公開 bucket、IAM 給使用者 |
| `immediately roll back` | 秒級回滾 | Cloud Run `update-traffic --to-revisions` | 重新建置部署 |
| `test in production without affecting users` | 零影響驗證 | `--no-traffic --tag` + tag URL | canary 1%（已有使用者） |
| `survive a zone failure` | 區域內冗餘 | Cloud SQL HA(REGIONAL)、Memorystore Standard、GKE regional | 單機、Basic tier、zonal cluster |
| `survive a region failure` | 跨區 | 多 region + Global LB + Spanner multi-region | Cloud SQL HA（只跨 zone） |
| `no VPN for internal app` | 零信任存取 | **IAP** | Cloud VPN、防火牆白名單 |
| `millions of end users sign in` | CIAM | **Identity Platform** | IAM |
| `rate limit calls to a third party` | 出向節流 | **Cloud Tasks** 佇列速率 | Pub/Sub、Cloud Armor |
| `schedule one task 30 min later` | 單一延遲 | **Cloud Tasks** `scheduleTime` | Pub/Sub |
| `multiple services must each process every event` | 扇出 | **多個 subscription** | 一個 subscription 多 consumer |
| `orchestrate multi-step with conditions` | 編排 | **Workflows** | 一串 Pub/Sub topic |
| `data must stay in <country>` | 資料落地 | 指定 **region**（+ resourceLocations 政策） | multi-region、global |

## 🎭 Part 2：八種誘答套路

### 套路 ①「服務根本不支援」
最容易砍掉的錯誤選項。看到就直接刪。

| 誘答 | 為什麼不可能 |
|---|---|
| Bigtable 加二級索引 | **Bigtable 沒有二級索引** |
| Firestore 做 JOIN 或複雜聚合 | Firestore 沒有 JOIN |
| Cloud Run 用 DaemonSet | Cloud Run 沒有節點概念 |
| Memorystore 開公開 IP | Memorystore 只有私有 IP |
| App Engine Flexible 縮到 0 | 它最少 1 個實例 |
| Cloud Tasks 的 dead-letter queue | **Cloud Tasks 沒有 DLQ** |
| Pub/Sub 對單一訊息設延遲 | 沒有 per-message delay |
| Cloud Armor 保護 L4 passthrough LB | 只支援 L7 / proxy LB |
| Binary Authorization 用 tag 部署 | **只能用 digest** |
| 修改已建立的 Firestore mode / bucket location | **不可變** |
| 縮短已 lock 的 retention policy | **不可逆** |

### 套路 ②「權限過大」
只要選項出現下列任一，幾乎可以直接砍：
- `roles/owner`、`roles/editor`、`roles/viewer`（basic roles）
- **default compute service account**
- `roles/storage.admin` 當成「只要讀一個 bucket」的答案
- **在 project 層級授權**，而題目其實只需要單一資源
- 下載/分發 **SA JSON 金鑰**
- 把祕密放在環境變數的部署設定、config 檔、或 git

### 套路 ③「治標不治本」
| 誘答 | 真正的問題 |
|---|---|
| 「提高資料庫機器規格」 | 連線池太大 / 缺快取 / N+1 查詢 |
| 「提高 timeout」 | 下游太慢 / 沒有分頁 / 沒有退避 |
| 「提高配額」 | 呼叫次數本身太多（應該批次/快取） |
| 「提高 max-instances」 | OOM 是**單一實例**的記憶體問題 |
| 「把警示門檻調高」 | 警示設計錯誤（該用 SLO burn rate） |
| 「手動修 30 個 CVE」 | 該換 minimal 基底映像 + CI gate |

### 套路 ④「過度工程」
題目只要 `high availability`，選項給你多區域多活 + Spanner multi-region → **過度**。
題目說 `simple`、`small team`、`cost-effective`，選項給你 Apigee / Service Mesh / 微服務拆分 → **過度**。
> **判準：在滿足需求的前提下選最簡單的。**

### 套路 ⑤「相似服務混淆」
| 常見混淆 | 分辨關鍵 |
|---|---|
| Secret Manager vs Cloud KMS | 存**祕密值** vs 管**金鑰** |
| Pub/Sub vs Cloud Tasks | 廣播 vs 派工 + 控速 |
| Eventarc vs Pub/Sub | GCP 事件 vs 自己發的事件 |
| Workflows vs Pub/Sub | 編排（有狀態） vs 協作（無狀態） |
| Apigee vs API Gateway | 完整 API 管理平台 vs 輕量閘道 |
| IAP vs Identity Platform | 存取**你的員工** vs 驗證**你的使用者** |
| IAM vs Firestore Security Rules | 服務帳戶/開發者 vs 客戶端終端使用者 |
| WIF vs WIF for GKE vs Workforce IF | GCP 外的機器 vs GKE Pod vs 人類使用者 |
| Cloud Build vs Cloud Deploy | CI（產生產出物） vs CD（晉升產出物） |
| Session affinity vs Session 儲存 | 效能最佳化 vs 狀態管理 |
| readiness vs liveness probe | 移出流量（不重啟） vs 重啟容器 |
| HPA vs VPA vs CA | 加 Pod vs 調 Pod 大小 vs 加節點 |
| Cloud CDN vs Memorystore | 邊緣靜態內容 vs 動態共享資料 |
| CMEK vs CSEK vs EKM | 你在 KMS 管 vs 你自己傳入 vs 外部 KMS |
| Nearline vs Coldline vs Archive | 30 / 90 / 365 天最短儲存期 |

### 套路 ⑥「舊版/已淘汰的服務」
| 誘答 | 現在的答案 |
|---|---|
| Container Registry (`gcr.io`) | **Artifact Registry** |
| Cloud Functions gen1 / gen2 獨立服務 | **Cloud Run functions** |
| Deployment Manager | Terraform / Config Connector |
| App Engine 給全新專案 | **Cloud Run** |
| Stackdriver | **Google Cloud Observability** |
| Cloud Debugger | 已淘汰 |
| `gsutil` | `gcloud storage`（`gsutil` 仍可用但非首選） |

### 套路 ⑦「忽略 at-least-once」
只要題目涉及 Pub/Sub / Eventarc / Cloud Tasks / Cloud Scheduler，而選項裡有「冪等」相關的做法，**那通常就是答案**。
反之，選項說「啟用 exactly-once 就不用冪等了」→ **錯**（處理完成但 ack 前崩潰仍會重跑）。

### 套路 ⑧「方向相反」
| 誘答 | 為什麼方向錯 |
|---|---|
| 用 `--ingress` 控制**出向**流量 | ingress 是入向；出向是 `--vpc-egress` |
| 用 Cloud NAT 讓外部連進來 | NAT 是讓內部連外 |
| 用 Cloud Armor 限制**我們呼叫第三方**的速率 | Armor 保護入向 |
| 給執行時 SA `cloudbuild.builds.editor` 來解 actAs | 應該給 Cloud Build SA 對執行時 SA 的 `serviceAccountUser` |

## 🧩 Part 3：多選題（Choose two/three）技巧

1. **先確認要選幾個** —— 漏看數量是最可惜的失分。
2. **先砍硬錯**（套路 ① ②），剩下的通常剛好是答案數。
3. **注意「互斥」選項**：如果兩個選項互相矛盾，通常只有一個是答案。
4. **注意「同一個答案的兩種說法」**：若兩個選項本質相同，很可能兩個都是答案，或兩個都不是。

## 📖 Part 4：讀題檢查清單（每題花 10 秒）

```
□ 有沒有「最」字？（most cost-effective / least overhead / fastest）
□ 有沒有規模數字？（millions / petabytes / per second）
□ 有沒有一致性要求？（strongly consistent / eventual OK）
□ 有沒有地理要求？（global / region / must stay in X）
□ 有沒有延遲要求？（sub-millisecond / single-digit ms / real-time）
□ 有沒有合規要求？（audit / immutable / retention / no keys）
□ 有沒有團隊/時程限制？（small team / tight deadline / cannot modify code）
□ 要選幾個答案？
```

> [!tip] 最有效的單一技巧
> **把題目最後一句話讀兩遍。** 專業級考題的真正約束幾乎都藏在最後一句（「…with the least operational overhead」、「…while minimizing cost」、「…without changing the application code」）。

## 🧠 Part 5：Google 的偏好順序（沒有其他線索時的預設）

```
運算：  Cloud Run > GKE Autopilot > GKE Standard > Compute Engine
身分：  附加 SA / WIF > impersonation > SA 金鑰（永不）
角色：  資源層級的 predefined role > 專案層級 predefined > custom > basic（永不）
祕密：  不存（WIF）> Secret Manager > 其他（永不）
資料：  代管 > 自建；能用 SQL 就用（除非規模/延遲不允許）
整合：  事件驅動/非同步 > 同步鏈式呼叫
部署：  不可變產出物 + 漸進式發布 + 可回滾
網路：  私有連線 > 公開 IP + 防火牆
觀測：  OpenTelemetry + 結構化 log + SLO
```
